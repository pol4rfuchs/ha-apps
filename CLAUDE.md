# ha-apps

Monorepo for Home Assistant apps (add-ons). Every top-level folder with a `config.yaml` is an app
that is built, versioned and released on its own. Remote: `pol4rfuchs/ha-apps`.

Binding rule catalog: skill `ha-apps-buildrules` (`references/appbuildrules.md`, port table in
`references/port-table.md`). Use the skill when working on a Dockerfile, `config.yaml`, `apparmor.txt`, translations or
workflows. Layout of an app folder and CI rules: `CONTRIBUTING.md`.
Open backlog: kept locally by the maintainer, not in the repo (`OFFENE_PUNKTE.md` is listed in `.gitignore`).

Layout: `<app>/` per app (folder with `config.yaml`), `.github/workflows/` (numbered), `scripts/` (`check_apparmor.py`,
`sync_version_badges.py`, `validate_wiki.py`), `wiki/` (wiki pages), `docs/`, manifests in the root directory.
The user wants lists, not git commands.

## Language

Everything in the repo is English: code, comments, runtime log messages, docs, wiki, CI/workflow comments, config comments,
commit messages, PR titles and PR descriptions. The only exception is `*/translations/de.yaml` and `en.yaml`, which keep both
languages. Chat replies to the maintainer stay in German.

## Commands

```bash
python -m yamllint -c .yamllint .                       # whole repo
python -m yamllint -f parsable -c .yamllint */config.yaml */translations .github
docker build --build-arg BUILD_ARCH=amd64 --build-arg BUILD_VERSION=test -t ha-test-<app> ./<app>
```

`hadolint`, `actionlint` and `shellcheck` are not installed locally. The stop hook starts them via Docker
(same images as the CI, pinned by digest in `.claude/hooks/stop_check.py`), but only if Docker Desktop is running
and the image is already present locally. Otherwise it reports "skipped", which is **not** a passed check.
`apparmor_parser` and `scripts/check_apparmor.py` need Linux and only run in the CI (workflow 29).

## Working rules

- **Never push or merge.** Only commit locally; the user pushes and merges themselves
  (additionally blocked in `.claude/settings.local.json`: `git push`, `gh pr merge`, `rm`, `git reset`).
- One branch and one PR per app, branch from `origin/main` with `--no-track`.
  PR title: Conventional Commit with an app scope (`fix(ntfy): …`, `feat(ts6_manager): …`, otherwise `chore:`/`docs(scope):`).
- `CHANGELOG.md` is generated by Release Please: **do not edit it by hand**. `version:` in `config.yaml` is synced from the
  Release Please manifest by workflow 05 and is not bumped for local tests. The only exception (catalog §7): a purely
  internal dependency change without an upstream change that users should get immediately; then raise `version:` by one patch
  level so HA shows an update.
- Build and test before every commit: start twice, each time in a new container with the same `/data`.
  Not testable without a Pi or HAOS: AppArmor in enforce mode, Supervisor option validation. Say so in the PR.
- Findings from the code alone are suspicions until they have been tested.
- For anything that may have changed since the training cutoff (base image tags, Supervisor, Actions behavior):
  research first, do not copy from the snapshot table in §16.
- Do not change AppArmor profiles in passing.
- No blanket search-and-replace "addon → app": folders, file names, slugs, image names, `map:` values such as `addon_config`
  and workflow names stay unchanged (catalog §17).
- No references to the former forge (Codeberg domains, Forgejo dot folders) in new lines; link Forgejo with
  `https://forgejo.org`. Exception only with the marker `forge-check:allow`. Workflow 00 checks this across the whole repo,
  so do not spell out these strings here either.
- No keys or passwords in the repo. Password options: schema `password`, no default.

## Structure that cannot be derived from the code

- A new app must also be entered in `addons.json`, `release-please-config.json`, `.release-please-manifest.json`.
- Host ports are unique across the whole repo (check the table in the skill before assigning a port).
- Options in `config.yaml` must take effect; `translations/en.yaml` and `de.yaml` stay in sync with the schema.
- Workflows are numbered (`00`–`30`); actions are pinned by commit SHA, runner `ubuntu-24.04`.
- Labels live in `.github/labels.yml`.
