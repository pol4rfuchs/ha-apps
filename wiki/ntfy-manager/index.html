🔔 ntfy Admin Console · HA Add-on

ntfy Manager

Web-based admin console for the ntfy add-on. Manage topic reservations, ACL rules and auth tokens, and watch messages in real time via SSE — all without CLI access to the container.

🏗️ Custom Add-on 🌐 Web UI 🔐 ACL / Token Mgmt 📡 SSE Live-Stream aarch64 · amd64
✨

Features

Complete admin console for ntfy — single-page HTML served by the add-on

📌

Topic Reservations

Create and manage reserved topics with read/write permissions for specific users.

📬

Message Browser

Browse cached messages per topic. Shows priority, tags, attachment links.

🔐

ACL Management

Manage user access control lists: create, edit, delete — without the ntfy CLI.

🪙

Token Management

Create, list and revoke auth tokens for ntfy via the ntfy REST API.

📡

SSE Live-Monitor

Subscribe to any topics via an SSE stream and watch messages arrive in real time.

💾

Topic Settings

Persistent topic settings (default priority, labels) stored in the add-on storage.

📦

Installation

Add the add-on via a custom repository or directly from the GHCR image

1

Add the repository

In HA → Settings → Add-ons → Add-on Store → ⋮ → Repositories → paste the URL:

https://github.com/pol4rfuchs/ha-apps
2

Install the add-on

Search for ntfy Manager in the store → Install. The image is pulled from GHCR (ghcr.io/pol4rfuchs/ntfy_manager).

3

Configure the ntfy endpoint

Set the options in the add-on — at least ntfy_base_url; for auth-protected instances additionally ntfy_auth_type with ntfy_username/ntfy_password (basic) or ntfy_bearer_token (bearer). Leaving them empty works too: then you log in in the panel.

4

Start the add-on & open the web UI

Start → open the panel via the HA sidebar (ingress). Optionally directly via http://<HA-Host>:8099.

ℹ️
Ingress and optional direct access The panel runs through HA ingress (sidebar, protected by your HA login). The host port 8099 is optional and can be removed in the network tab of the add-on. The credentials from the add-on configuration only apply through ingress; on the direct port the panel always requires an ntfy login.
⚠️
External access Recommendation: not recommended, VPN only. The panel manages ntfy users, tokens and ACLs. If it still has to be published: reverse proxy with TLS plus additional access control. The session cookie does not carry the Secure flag.
⚙️

Configuration

Options and schema fields of the add-on

OptionTypeDefaultDescription
ntfy_base_url url http://homeassistant.local:4280 Address of the ntfy server, e.g. the internal address of the ntfy add-on or an external URL.
ntfy_auth_type list basic none / basic / bearer: type of authentication towards ntfy.
ntfy_username str? "" Username (for basic).
ntfy_password password? "" Password (for basic).
ntfy_bearer_token password? "" Access token (for bearer).
default_topics list ha-alerts, ha-info, ha-notify, ha-system Suggested topics in the panel.
allow_login_override bool true Allows logging in with other ntfy credentials in the panel. Set to false for kiosk setups.
log_level list info debug / info / warn / error.
config.yaml · options
options:
  ntfy_base_url: "http://homeassistant.local:4280"
  ntfy_auth_type: "basic"
  ntfy_username: ""
  ntfy_password: ""
  ntfy_bearer_token: ""
  default_topics:
    - ha-alerts
    - ha-info
    - ha-notify
    - ha-system
  allow_login_override: true
  log_level: "info"
⚠️
Docker-internal URL (optional) If both add-ons run on the same Supervisor, the Docker-internal address http://a0d7b954-ntfy:80 can be used instead of the external URL — no TLS overhead, no NAT loopback. The default value http://homeassistant.local:4280 works as well.

Web UI

Structure and use of the admin console

The admin console is a single-page HTML interface served directly by the add-on. All data comes live from the ntfy REST API.

AreaFunction
DashboardServer version, user count and message statistics at a glance.
Topic ReservationsTable of all reserved topics. Create / edit / delete inline.
Message BrowserSelect a topic → show cached messages with priority, tags, click URL.
ACLManage user access rules: which user may read/write which topic.
Token ManagerCreate (label, expiry date) and revoke auth tokens.
Live MonitorSSE subscribe to N topics at the same time — messages appear in real time.
Topic SettingsAdd-on-side configuration per topic (default priority, label). It is persisted.
🔐

ACL & Token Management

Access control for ntfy via the web UI instead of the CLI

ntfy Manager replaces the direct use of the ntfy user and ntfy access CLI commands. Prerequisite: ntfy runs with auth-file in its configuration.

ntfy server.yml (Prerequisite)
auth-file: /data/user.db
auth-default-access: deny-all

With auth enabled there is the admin user (or a token with admin rights) that you have to store in the add-on. After that you can, in the UI:

→

Create a user

ACL tab → "New User" → username + password → choose a role (user or admin).

→

Set topic access

Topic Reservations → select a topic → set owner + permissions (read-write / read-only / deny).

→

Generate a token

Token Manager → "New Token" → enter a label, optional expiry date → copy the token for the HA rest_command.

✅
Recommendation: token instead of password in HA Create a dedicated token for HA automations (topic: ha-*, no expiry) and store it in secrets.yaml — not the admin user directly.
📡

SSE Live-Monitor

Watch messages in real time

The live monitor opens a Server-Sent Events stream to the ntfy API that is passed through the backend of this add-on. Several topics can be subscribed at the same time.

ntfy SSE endpoint (internal)
GET http://a0d7b954-ntfy:80/ha-alerts,ha-info,ha-system/sse
Authorization: Bearer <token>
FieldDescription
idMessage-ID (12-char random)
topicWhich topic received the message
titleMessage title (optional)
messageMessage text
priority1 (min) – 5 (max urgent)
tagsEmoji / keyword tags as an array
clickClick action URL (optional)
💡
Connection through the add-on The SSE stream is passed on to ntfy by the add-on's backend (/sse); the credentials stay in the encrypted cookie and do not reach the browser. The add-on and ntfy must be able to reach each other, the browser only needs access to the panel.

Troubleshooting

Common problems and solutions

ProblemCauseFix
"Cannot connect to ntfy" Wrong ntfy_base_url or the ntfy add-on is not started Check the Docker-internal URL: http://a0d7b954-ntfy:80. Both add-ons must be running.
401 Unauthorized ntfy runs with auth, token is missing or wrong Set ntfy_auth_type to bearer and store the token under ntfy_bearer_token (or basic with user/password), or log in in the panel.
ACL tab empty ntfy configured without auth-file Set auth-file: /data/user.db in the ntfy server.yml and restart ntfy.
SSE stream breaks off NPM timeout or proxy buffering In the NPM proxy host: set proxy_read_timeout 3600; and proxy_buffering off; as custom config.
Web UI not reachable Port conflict or the add-on is not started Check the logs (bashio::log.info). Check the port mapping in the add-on.
NPM custom config for SSE
proxy_read_timeout 3600s;
proxy_buffering off;
proxy_cache off;
chunked_transfer_encoding on;
