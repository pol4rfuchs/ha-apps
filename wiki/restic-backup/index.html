Home

Overview

#home

Restic Backup runs restic on a cron schedule against a configurable set of mapped folders (defaults: /homeassistant, /addon_configs, /ssl). It initializes the repository automatically on first start, applies retention (forget --prune) after each successful backup, and sends an ntfy notification after every run — success or failure.

cron (03:00 daily) → restic backup → local or S3/MinIO/B2 repo
                                    → forget --prune (retention)
                                    → ntfy notification (success/failure)
This add-on only performs the backup side. There is no one-click restore, by design — see Restore.

Installation

Install the Add-on

#installation

#Step 1 — Add Repository

https://github.com/pol4rfuchs/ha-apps

#Step 2 — Install & Configure

  1. Search for Restic Backup in the Add-on Store, click Install.
  2. Set restic_password to something strong, and back it up somewhere outside this add-on.
  3. Leave repository as the local default, or point it at a remote (e.g. s3:https://minio.local/bucket-name) and fill in aws_access_key_id / aws_secret_access_key if required.
  4. Optionally set ntfy_url + ntfy_topic — fits naturally into an existing ntfy topic setup.

#Step 3 — Verify

  1. Start the add-on. Check the log for Repository initialized. on first run.
  2. Enable run_on_start once to verify the config works, then turn it back off and let cron_schedule handle it going forward.

Advanced

backup_paths vs. map

#backup-paths

backup_paths only lists which mounted folders restic should walk — it does not mount anything itself. Each path listed must already be exposed via the add-on's own map: block in config.yaml (currently: homeassistant_config:ro, addon_configs:ro, media:ro, share:rw, ssl:ro).

Adding a path to backup_paths that isn't mapped does nothing — the directory simply won't exist inside the container. To back up /media too, add it to both backup_paths and confirm media:ro stays in map:.
♻️

Recovery

Restore (Manual, By Design)

#restore

This add-on only performs the backup side of the restic workflow. Restoring is intentionally a manual, out-of-band step — there is no one-click restore button, to avoid an accidental data-loss action.

To restore, open a shell with access to the same repository and run restic directly:

export RESTIC_REPOSITORY=/share/restic-backup/repo   # or your configured repository
export RESTIC_PASSWORD=your-restic-password
restic snapshots                 # list available snapshots
restic restore latest --target /path/to/restore/to

For remote (S3/MinIO/B2) repositories, also export the same AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY / AWS_DEFAULT_REGION used by the add-on.

🔔

Notifications

ntfy Alerting

#ntfy

A notification is sent after every run, success or failure, if ntfy_url/ntfy_topic are configured. Failures go out at urgent priority so they stand out from routine success pings.

Fits naturally into an existing ntfy topic setup — e.g. reusing an ha-system-style topic alongside other infrastructure alerts.

Security

Secrets & AppArmor

#security

#Secrets

OptionNote
restic_passwordEncryption password for the entire repository. No recovery mechanism if lost — keep a copy outside this add-on.
aws_secret_access_key / aws_access_key_idOnly for S3/MinIO/B2-compatible remotes. Leave empty for the local repository.
ntfy_passwordOnly needed if the ntfy topic requires authentication.

All three are declared as password schema types, so the Supervisor UI masks them.

#AppArmor

The bundled apparmor.txt profile covers: the s6-overlay baseline paths, the mapped read-only backup sources (/homeassistant, /addon_configs, /media, /ssl), the read-write repository target (/share), and dcron's crontab files plus restic's own lock file under /tmp.

Extra mapped folders beyond the current map: block need a matching read (or read-write) AppArmor rule, or restic will silently fail to read/write it under enforcement.

Troubleshooting

Known Symptoms & Fixes

#troubleshooting
SymptomCauseFix
Backup fails with "directory not found"Path in backup_paths isn't covered by map:.See backup_paths vs. map — add the matching map entry.
Remote repo connection fails (S3/MinIO)Missing or wrong AWS credentials/region.Verify aws_access_key_id, aws_secret_access_key, aws_default_region.
No ntfy notification receivedntfy_url/ntfy_topic unset, or auth required but not set.Set both, plus ntfy_username/ntfy_password if the topic needs auth.
Lost restic_passwordNo recovery mechanism exists.The repository is unrecoverable — start a new one and keep the new password backed up externally.
