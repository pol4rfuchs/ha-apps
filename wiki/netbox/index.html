Home

Overview

#home

NetBox is an IP address management (IPAM) and data center infrastructure management (DCIM) tool. This Home Assistant app runs the NetBox build of netbox-docker together with PostgreSQL 18 and Valkey 9 in one container — nothing else has to be set up.

#Current Scope

  • Web UI and REST API directly on port 8001 (no Ingress), with NetBox's own login on every page
  • PostgreSQL and Valkey listen on 127.0.0.1 inside the container only
  • Secrets (SECRET_KEY, API token pepper, database password) are generated at the first start and stored in /data
  • Optional plugins (pinned PyPI packages) and an extra.py for settings without an option
  • aarch64 and amd64; about 1 GB of free RAM recommended. Not measured on a Raspberry Pi yet.
Status wip: AppArmor in enforce mode and the Raspberry Pi behaviour (migration time, RAM) have not been tested yet.

First Start

Install the App

#installation
  1. Open Settings → Apps → App Store and add the repository:
https://github.com/pol4rfuchs/ha-apps
  1. Reload the store, open NetBox, click Install.
  2. Set allowed_hosts to the addresses you open NetBox with (host IP, reverse-proxy domain). Empty means any host is accepted and a warning is logged.
  3. Start the app and wait for Starting NetBox on port 8001 in the log.
  4. Open http://<ha-host>:8001 and log in.

#Admin account

There is no default account. Either set admin_password before the first start, or leave it empty: a random password is generated, printed once in the app log and saved in initial_admin_password.txt in the app's configuration folder (/addon_configs/<id>_netbox/). Anyone who can read the app log can see it, so change it after the first login and delete the file.

The first start (and every update that changes the database) applies migrations. On a Raspberry Pi this takes several minutes. Until it is done, port 8001 answers 503 with a short message and the health check counts the app as healthy.

Extensions

Plugins & extra.py

#plugins

Every plugin entry pins an exact version, for example:

plugins:
  - module: netbox_qrcode
    pip: "netbox-qrcode==1.0.0"
  • Ranges, URLs and options are refused and the app stops with a message.
  • Packages are downloaded from PyPI only when the list changes (or a NetBox update changes its dependencies) and kept in /data/netbox/plugins. This is the only step that needs the Internet.
  • NetBox's own dependency versions are used as constraints; a conflicting plugin makes the install fail and the app does not start — remove the entry again.
  • Install only plugins you trust: they run inside NetBox with access to its database. Removing an entry leaves the plugin's tables in the database.

#extra.py

Settings without an option (LDAP, SSO, e-mail, PLUGINS_CONFIG, …) go into extra.py in the app's configuration folder. It is read at every start as Python code in the NetBox settings.

PLUGINS_CONFIG["my_plugin"] = {"some_setting": "value"}
EMAIL = {"SERVER": "mail.example.org", "PORT": 587, "USE_TLS": True, "FROM_EMAIL": "netbox@example.org"}
Only put code in this file that you wrote or have read. A syntax error stops NetBox from starting. If a plugin itself needs the Internet, add ISOLATED_DEPLOYMENT = False.

Access

Local and External Access

#access

Local (LAN): open http://<ha-host>:8001. NetBox has its own login (users, groups, object permissions, API tokens) and every page needs it. The app serves plain HTTP; passwords and API tokens cross the network unencrypted unless you put a TLS reverse proxy in front.

External (internet): recommendation VPN only. A NetBox database describes your whole network, so it is a target. If you still publish it, use only a reverse proxy with TLS, never forward port 8001 directly, set allowed_hosts to the public domain and csrf_trusted_origins to https://<that domain>, use strong passwords and per-person users with minimal permissions.

The proxy connects to http://<ha-host>:8001; NetBox trusts X-Forwarded-* headers of private network addresses only.

Security

Privacy, Data & Backup

#privacy

#Outbound connections

NetBox does not call the Internet by itself: census reporting and the Copilot agent are off, ISOLATED_DEPLOYMENT is on, there is no release check, and the bundled documentation has its Google Fonts links removed at build time. Links in the UI only open when you click them. Plugin installation is the one exception (see Plugins).

#Data and backup

  • Everything lives in /data/netbox: postgresql, valkey, media, scripts, reports, plugins, secrets.
  • backup: cold: the app is stopped briefly so the PostgreSQL files are consistent. Restore as a whole — the secrets belong to the database.
  • The app does not migrate PostgreSQL across major versions (18 now). On such an update it refuses to start and says so; make a pg_dump from the running old app first.
  • NetBox updates migrate the database automatically at the next start — take a backup first.

Troubleshooting

Known Symptoms & Fixes

#troubleshooting
SymptomLikely causeFix
Bad Request (400)The address in the browser is not in allowed_hosts.Add it to allowed_hosts.
CSRF verification failed behind a proxyThe proxy origin is unknown.Add https://<domain> to csrf_trusted_origins.
Page shows “NetBox is starting” (503)A database migration is still running.Wait; check the log.
Memory overcommit must be enabled in the logHint from Valkey about a host setting.Harmless for the app; background saves could fail if the host is nearly out of memory.
App does not start after a plugins changeInvalid entry or pip conflict.Read the log; the message names the entry or the pip error.
