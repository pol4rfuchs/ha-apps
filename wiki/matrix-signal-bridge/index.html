Home

Overview

#home

Signal Bridge connects Signal to your self-hosted Matrix Synapse homeserver via mautrix-signal as an application-service bridge. It runs as a standalone, isolated add-on — no shared container with other bridges.

Experimental. The add-on is marked stage: experimental. Documented upstream at docs.mau.fi.
🚀

Installation

Install & Link Synapse

#installation
  1. Install and start the add-on.
  2. Set homeserver_address / homeserver_domain (address of the Matrix Synapse add-on) and db_type (SQLite or Postgres).
  3. On first start the bridge generates config.yaml (from your options) and registration.yaml, which is copied to /share/signal_bridge_registration.yaml.
  4. In the Matrix Synapse add-on enable signal_bridge_enabled and restart Synapse — it only reads the appservice registration then.
  5. From any Matrix client, DM @signalbot:<your-domain> and send login.
⚙️

Login

Link as a secondary device

#login
  • Send login to the bridge bot and scan the QR code in Signal under Linked Devices (not an in-app QR scanner).
  • On first login Signal asks whether to transfer message history — optional, but recommended for full context in Matrix.
🔐

Secrets

Tokens & Registration

#secrets

as_token / hs_token in /data/registration.yaml are generated automatically on first registration. Do not change them afterwards — otherwise Synapse loses its link to the appservice and all bridged rooms and users break.

The bridge writes registration.yaml to /share/signal_bridge_registration.yaml. Synapse reads it only when signal_bridge_enabled is enabled (restart required).

💾

Backup

What to Back Up

#backup
  • /data contains config.yaml, registration.yaml and, with SQLite, the complete bridge database. Back it up — Signal must be linked again after a restore otherwise.
  • /share/signal_bridge_registration.yaml is reproducible from /data/registration.yaml (re-copied on the next start if missing) and need not be part of the backup.
🦀

Details

Build Notes (Rust + Go)

#notes

Signal is the only one of the three bridges that needs a Rust build step in addition to Go (libsignal_ffi.a, the official Signal protocol in Rust). The build follows the official mautrix/signal Dockerfile: stage 1 builds libsignal_ffi.a via build-rust.sh, stage 2 links Go against it via build-go.sh. Build time is noticeably longer than for WhatsApp/Telegram — a CI-time effect only, with no impact on runtime RAM.

⚠️

Limits

Known Limitations

#limits
  • Registering as a Signal primary device is not supported — only linking as a secondary device (official app or signal-cli).
  • Encryption (Megolm) must be enabled on both sides (bridge option encryption plus the Matrix client) to get encrypted portal rooms.
