Home

Overview

#home

Linkwarden is a self-hosted bookmark manager that keeps a copy of every page you save: a PDF, a screenshot, a copy of the web page and a readable view. This Home Assistant app runs the web app and the worker of the official Linkwarden image together with PostgreSQL in one container — nothing else has to be set up.

#Current Scope

  • Web UI and API directly on port 3200 (no Ingress), with Linkwarden's own login
  • PostgreSQL listens on 127.0.0.1 inside the container only
  • Secrets (database password, login secret) are generated at the first start and stored in /data
  • Built-in Chromium for PDFs and screenshots, or an optional remote browser such as Browserless
  • Tested on amd64 only; aarch64 (Raspberry Pi) is built by the pipeline but not tested yet. RAM use not measured. AppArmor is switched off.
Status experimental: the Raspberry Pi behaviour, AppArmor (disabled), Supervisor backup and restore and a real Browserless instance have not been tested yet.

First Start

Install the App

#installation
  1. Open Settings → Apps → App Store, choose Repositories in the top right menu and add https://github.com/pol4rfuchs/ha-apps.
  2. Select Linkwarden and click Install.
  3. Set public_url to the address you will open Linkwarden with. Logging in only works through this address.
  4. Start the app and wait for Starting Linkwarden on port 3200 in the log. The first start creates the database.
  5. Open http://<ha-host>:3200 and sign up.

#Sign-up is open until you close it

Anyone who can reach port 3200 can create an account (tested: the API accepts a new user without a login). After you created your own account, switch on disable_registration and restart the app (tested: new accounts are then refused). Keep the port inside your network in any case.

Configuration

App Options

#configuration
OptionDefaultDescription
log_levelinfodebug, info, warning or error. Applies to Linkwarden (web and worker) and PostgreSQL.
public_url(empty)Address you open Linkwarden with, including http:// or https:// and the port. Empty = http://localhost:3200 with a warning in the log.
browser_url(empty)Optional remote browser (protected password field, the URL usually holds a token). Empty = built-in Chromium. See Remote Browser.
disable_browserfalseSwitches the archiving of web pages off completely: in a test all four formats stayed unavailable. Chromium was still started; RAM was not measured.
disable_registrationfalseRefuses new accounts. Create your own account first, then switch it on; it does not remove existing accounts.
archive_take_count1Links the worker takes per round, for archiving and automatic tagging (1–10). 1 is the gentlest for a Raspberry Pi.

#Minimal configuration

public_url: "http://192.168.1.10:3200"

Browser

Remote Browser

#browser

A remote browser takes the load of PDFs and screenshots off the Raspberry Pi. It must speak the Chrome DevTools protocol, for example Browserless. Set browser_url to ws://<host>:3000?token=<token> or, for a Chromium with remote debugging, http://<host>:9222.

  • The browser is checked every time the worker starts. Reachable: Using the remote browser at <host>:<port>. Not reachable: the built-in Chromium is used and a warning is logged; the app does not crash.
  • The worker does not look again while it runs. When the remote browser is back, restart the app.
  • Only the host is logged. Credential-like query parameters (token=, apikey=, key=, password=, secret=) are replaced by <hidden> in the log, also in the line the Linkwarden worker prints itself.
Tested with a Chromium with remote debugging as a stand-in. A real Browserless instance was not tested with this app.

Access

Local and External Access

#access

Local (LAN): open http://<ha-host>:3200. Linkwarden has its own login. The app serves plain HTTP, so passwords cross your network unencrypted; use a reverse proxy with TLS if that matters to you.

External (internet): recommendation VPN only. Bookmarks and archived pages can contain private data, and sign-up is open. If you still publish it, use only a reverse proxy with TLS, never forward port 3200 directly, and set public_url to the public https:// address.

The proxy connects to http://<ha-host>:3200.

Security

Data & Backup

#privacy

#What the app sets on purpose

  • Database password and login secret are generated at the first start, stored in /data/linkwarden/secrets and never shown. The database password is set again at every start.
  • Linkwarden does not archive addresses in private networks. In a test a page on a Docker-internal address was refused; other private addresses were not tried. That is its own protection against requests to internal services; the app does not switch it off.
  • PostgreSQL, the web app and the worker run as unprivileged users. If PostgreSQL or the web app crashes (also when the system kills it for lack of memory) the container stops; the worker is restarted automatically.

#Data and backup

Backup type cold: the Supervisor stops the app, copies /data and starts it again. Everything lives in /data/linkwarden: postgresql, library (the archives, the big part) and secrets. Restore the backup as a whole.

The app does not migrate PostgreSQL across major versions (it is 15 now); an update with a new major version makes it refuse to start and say so in the log. There is no automatic migration and no tested dump and restore path, so keep a backup and a JSON export. Backup and restore through the Supervisor is not tested yet.

#Moving from another Linkwarden

Use the JSON export of the old installation and import it here (both are in the Linkwarden settings). Links, collections and tags are imported; every page is archived again. Pages that no longer exist have no snapshot afterwards, so keep the old installation (stopped) until everything is archived again.

Troubleshooting

Known Symptoms & Fixes

#troubleshooting
SymptomLikely causeFix
Login returns to the login page or failspublic_url does not match the address in the browser.Set it to the exact address, including http/https and the port.
A link from your own network is not archivedLinkwarden blocks private network addresses.Not possible with this app; only public addresses are archived.
The remote browser at <host> is not reachableWrong address, port or token, or the browser is down.The built-in Chromium is used meanwhile. Fix the address and restart the app.
A page has no PDF or no screenshotThe page blocks headless browsers or loads very slowly.The other formats are still created.
The app stops at start and names another PostgreSQL versionThe data folder was written by a different major version.See Data & Backup.
