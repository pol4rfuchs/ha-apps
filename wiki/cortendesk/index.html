Home

Overview

#home

CortenDesk is an experimental Home Assistant app that bundles a RustDesk management console (devices, users, address books, groups) with the RustDesk ID server (hbbs) and relay (hbbr) in one container. It is a thin wrapper around the upstream image ghcr.io/marcpope/cortendesk.

#Current Scope

  • Console with its own login (not behind Home Assistant Ingress), reachable on port 21114
  • Embedded ID server and relay (CortenDesk server fork, based on rustdesk-server 1.1.16 plus a fix for signed-in clients from 1.4.1)
  • Optional built-in browser client (native_webclient)
  • SQLite database and server key pair persisted in /data, cold backup
  • aarch64 and amd64; the AppArmor profile is an untested draft and is not loaded (apparmor: false)
Unofficial community app: it is neither supported nor endorsed by the upstream author. Report packaging problems (wrapper, options, Home Assistant integration) in pol4rfuchs/ha-apps, problems in CortenDesk itself upstream.
🚀

Installation

Install the App

#installation
  1. Open Settings → Apps → App Store and add the repository:
https://github.com/pol4rfuchs/ha-apps
  1. Reload the store, open CortenDesk, click Install.
  2. Set app_url and admin_password in the configuration. Both are empty by default on purpose: there is no default password.
  3. Start the app and open the console at http://<ha-host>:21114. Sign in as admin_user with admin_password.
As long as app_url or admin_password is empty, the app stops right after the start and writes the reason to the log.

Clients

Connect RustDesk Clients

#clients

In the network settings of every RustDesk client enter:

Client fieldValue
ID server<host> (port 21116)
Relay server<host> (port 21117)
API serverthe value of app_url
KeyPublic key from the log (key … in the line server …) or from the console

#LAN and internet with the same instance

hbbs announces one relay address to all clients. If that address is a LAN IP, relayed sessions from outside hang. Use a hostname that resolves internally and externally (split DNS) and set it as app_url or in id_server / relay_server.

Configuration

App Options

#configuration
OptionDefaultDescription
app_url(empty, required)Public address as your clients reach it, including scheme and console port, e.g. http://rd.example.com:21114. The host part is announced to clients as ID server (:21116) and relay (:21117). Do not use localhost.
admin_useradminFirst administrator. Only used on the very first start, while no user exists.
admin_password(empty, required)Password of the first administrator, protected password field. Later changes of the option do not change the password; do that in the console.
native_webclientfalseEnable the browser client. It uses the WebSocket bridge to hbbs/hbbr, which is not published on the host.
id_server(empty)ID server as host:port. Empty = host from app_url with port 21116.
relay_server(empty)Relay as host:port. Empty = host from app_url with port 21117.
downloads_max_mb512Upload limit for client installers under System → Client Downloads (1–4096 MB). 512 is the upstream default.
log_levelINFODEBUG, INFO, WARNING or ERROR. One setting for the console and the ID/relay server.

#Minimal configuration

app_url: "http://rd.example.com:21114"
admin_user: "admin"
admin_password: "choose-a-strong-password"

Network

Ports

#ports
PortPurposePublished
21114/tcpConsole (container port 8080)yes
21115/tcphbbs NAT type testyes
21116/tcp + 21116/udphbbs ID serveryes
21117/tcphbbr relayyes
21118/tcp, 21119/tcpWebSocket bridge hbbs / hbbrno, internal only
Never map 21118/21119. hbbs and hbbr trust unchecked X-Forwarded-For headers there. They listen on all addresses inside the container, so they are reachable from other apps in the internal Docker network of Home Assistant. With host_network: true they would be open to the whole LAN.

Access

Local and External Access

#access

Local (LAN): the console runs directly on port 21114 (http://<ha-host>:21114), not through Ingress. It has its own login. RustDesk clients in the LAN talk directly to the ID server (21115/21116) and the relay (21117).

External (internet): restricted, OK. For clients outside it is enough to forward 21115–21117/TCP and 21116/UDP on the router; the clients verify the server key. Do not expose the console (21114) directly: put it behind a reverse proxy with TLS or reach it over VPN. Never forward 21118/21119.

The browser client needs HTTPS (or localhost) for voice calls, so use a TLS reverse proxy for it.

🔒

Security

Privacy, Data & Backup

#privacy

#Outbound connections

The app calls nothing on the internet by itself: the GitHub update check is switched off (CORTENDESK_UPDATE_CHECK=false) and the web UI loads no external scripts, fonts or trackers. Only when you configure it in the console, CortenDesk talks to external services (Apprise notifications, SMTP, FTP/FTPS or S3 backup copies, OIDC sign-in). The menu entry “Build Installers” is a plain link to a third-party service and opens only when you click it.

#Data and backup

  • Everything lives in /data (SQLite database in /data/db/cortendesk.sqlite, server key pair, app key, uploads) and is part of Home Assistant backups.
  • backup: cold: the app is stopped briefly so the SQLite files are consistent.
  • Do not lose the key pair. Without /data/rustdesk/id_ed25519 every client has to be set up again.
  • Since upstream 1.13.0 the console also writes its own backups to /data/backups (daily 03:30). They contain the app key and all secrets and end up in the Home Assistant backup too, so treat them like passwords.

Troubleshooting

Known Symptoms & Limitations

#troubleshooting
SymptomLikely causeFix
App stops right after startapp_url or admin_password is empty.Set both options; the reason is in the log.
Relayed sessions from outside hangThe relay address handed out by hbbs is a LAN IP.Use a hostname that resolves internally and externally, or set relay_server.
Log shows addresses from 172.30.x.x, P2P failsIn bridge mode with mapped ports hbbs may not see the real client IP (UDP is untested).Everything then runs over the relay. As a last resort switch to host_network: true (console then listens on fixed port 8080, 21118/21119 become reachable in the LAN).
connect() failed … /api/server/policy in the nginx log at starthbbs asks the console before php-fpm is ready.Harmless, disappears after a few seconds.
Changed admin_password has no effectThe option only applies on the very first start.Change the password in the console.
  • AppArmor is off (apparmor: false). The image runs supervisord as root with php-fpm, nginx, hbbs and hbbr; the shipped profile is an untested draft in complain mode and is not loaded.
  • SQLite only. Enough for a small number of devices; a MariaDB connection is not implemented.
  • Updates arrive through the app version, not through the console.
