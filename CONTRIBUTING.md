# Contributing

This repository is a monorepo of Home Assistant apps (add-ons). Each app lives in its own
top-level folder and is built, versioned and released independently.

## Layout of an app folder

| File | Purpose |
|---|---|
| `config.yaml` | Home Assistant app definition (options, schema, ports, `map`, `apparmor`) |
| `Dockerfile` | Image build; build metadata lives here, there is no `build.yaml` |
| `README.md`, `DOCS.md` | Overview and detailed documentation (including a section on local and external access) |
| `translations/en.yaml`, `translations/de.yaml` | Option descriptions, kept in sync with the schema |
| `icon.png`, `logo.png` | Store images |
| `apparmor.txt` | AppArmor profile |
| `CHANGELOG.md` | Generated by Release Please, do not edit by hand |

New apps are also listed in `addons.json`, `release-please-config.json` and
`.release-please-manifest.json`.

## Rules that CI enforces

- **One pull request per app.** The PR title becomes the squash-merge commit message and must be
  a Conventional Commit with an app scope: `fix(ntfy): …` or `feat(ts6_manager): …`. Housekeeping
  may be scopeless: `chore: …`, `docs(nextcloud): …`. Workflow `18` checks this. GitHub proposes
  the branch name as title, so set the title yourself.
- Only `feat`/`fix` commits trigger a release. Release Please then opens a release PR for the app
  (`chore(main): release <app> x.y.z`); merge release PRs one at a time.
- Squash-merge only.
- Options in `config.yaml` must do something. Passwords use the `password` schema type and never
  ship with a default value.
- Host ports are unique across the whole repository.
- Workflows `14` (actionlint), `12` (hadolint) and `13` (yamllint) must pass.

## Test before you open a pull request

Build the image and run it the way the Supervisor does:

```bash
docker build --build-arg BUILD_ARCH=amd64 --build-arg BUILD_VERSION=test -t ha-test-<app> ./<app>
docker volume create ha-test-data
# put an options.json with your test options into the volume, then start a new container
docker run --rm -v ha-test-data:/data ha-test-<app>
```

- Start the app twice with the same `/data` volume, in a new container each time: first start and
  restart behave differently in many apps.
- Run `hadolint`, `shellcheck` and `yamllint` on what you changed.
- Things Docker cannot show: AppArmor in enforce mode and the Supervisor's own option validation.
  Say in the PR if you could not test them.

## Labels and issues

Labels are defined in `.github/labels.yml` and synced by workflow `15` without pruning. If a
workflow sets a label that is not listed there, add it to the file.
